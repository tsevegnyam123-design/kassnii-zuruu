# GS25 Portal v2 — Менежер + ажилтны портал

## Шинэ шаардлага

- **Google Sheets огт ашиглахгүй.** \`index.html\` дахь \`opensheet.elk.sh\` хаягуудыг арилгасан.
- **Ажилтны хувийн мэдээллийн анкет цуглуулахгүй.** Гэрийн хаяг, Google Maps, холбоо барих хүн, утас, имэйл нэхэх хэсэг байхгүй.
- Менежер ажилтны **нэвтрэх код (ID)**, **дэлгэцэнд харагдах нэр**, **албан тушаал (BM/SL/Staff)**, **level**, **4 оронтой PIN**-ийг бүртгэнэ. Салбар менежерийн өөрийн бүртгэлээс авна.
- Ажилтан код + PIN-ээр нэвтэрч өөрийн ээлж, урьдчилсан цалин, кассын зөрүү ба тайлбарыг харна.
- Менежер сарын хүснэгт дээр өглөө/өдөр/шөнийн ээлж сонгоход тэр даруй батлагдаж хадгалагдана.
- Менежер кассын зөрүүг ажилтанд оноож огноо, дүн, тайлбартай хадгална.
- Менежер ажилтны PIN-ийг дахин олгож болно. **Хуучин PIN-ийг харуулах боломжгүй.**
- Нэмэлт баталгаажуулалт (OTP/MFA) байхгүй.

Эдгээрээс цалингийн урьдчилсан тооцоо хийхдээ хуучин \`calculateEstimate()\`-ийн дүрэм ашиглаж байна: 8 цаг/батлагдсан хоног, өдрийн ээлжинд 2.25 шөнийн цаг, шөнийн ээлжинд 6.25 шөнийн цаг, шөнийн тариф ×1.2, хоол 6,000₮, унаа 4,000₮, албан тушаал/түвшний үндсэн цалин, НДШ 11.5%, ХХОАТ 10% ба хөнгөлөлт, урьдчилгаа. **Энэ нь урьдчилсан цалин:** баяр, илүү цаг, KPI/SOP зэрэг хуучин Google Sheet-ийн бусад нэмэлтүүдийг одоогоор оруулаагүй. Бүрэн албан ёсны бодит цалин гэж ойлгож болохгүй.

Кассын зөрүүг цалингаас автоматаар хасдаггүй. Бүртгэлийг засахын оронд тайлбартай эсрэг дүнгийн мөр бүртгэхээр төлөвлөсөн.

## Архитектур

- Frontend: \`index.html\` (vanilla HTML/CSS/JS)
- Backend: \`api/portal.js\` — Vercel Node Serverless Function, **зөвхөн HTTPS** 
- Database: private Supabase Postgres, schema \`database/portal_v2.sql\`
- Auth: сервер дээр 4 цифр PIN-ийг bcrypt (\`pgcrypto crypt\`) hash-ээр шалгана. **5 удаа буруу оруулбал 15 минут түгжинэ.** Сервер случайгаар 256 бит session token үүсгэж, браузерт HttpOnly, Secure, SameSite=Strict cookie өгнө; DB-д зөвхөн hash-г нь хадгална.
- Эрх: \`access_role\` ба \`branch_code\` серверээс шалгагдана; ажилтан бусдын мэдээллийг API-аар авахгүй. Менежер зөвхөн өөрийн салбарын ажилтанд өөрчлөлт хийнэ.
- UI дээр хадгалагдсан PIN харагдахгүй; PIN plaintext GitHub, localStorage, Sheets-д байхгүй.

## Суурилуулалт

1. GitHub PR-ийн кодыг тусад нь шалгаж, шинэ **Vercel төсөл** (staging) дээр deploy хийнэ. **GitHub Pages өөрөө \`/api/portal\`-ийг ажиллуулахгүй.** Тиймээс зөвхөн Pages дээр нээвэл нэвтрэхгүй.
2. Supabase төсөлд \`database/portal_v2.sql\`-ийг администратор хянаж, SQL Editor дээр нэг удаа ажиллуулна. Энэ SQL хуучин хүснэгтийг өөрчлөхгүй; шинэ \`portal_v2_\` хүснэгтүүд үүсгэнэ.
3. Vercel серверийн Environment Variables хэсэгт **\`SUPABASE_URL\`** болон **\`SUPABASE_SERVICE_ROLE_KEY\`** оруулна. \`.env.example\`-д нууц утга бүү бич. \`SUPABASE_SERVICE_ROLE_KEY\`-ийг client-side \`NEXT_PUBLIC_\` гэх мэтээр хэзээ ч нийтэлж болохгүй.
4. Анхны менежер 115091-ийг админ Supabase SQL Editor-оор үүсгэнэ. Жишээ:

   \`\`\`sql
   insert into public.portal_v2_accounts
       (employee_code,pin_hash,display_name,branch_code,access_role,salary_role,level)
   values
       ('115091', extensions.crypt('<PIN-ээ энд оруул>',extensions.gen_salt('bf',12)),
        'Салбарын менежер','<таны салбарын код>','manager','BM',1);
   \`\`\`

   PIN-ийг албан ёсны GitHub, чат, эсвэл log-т хуваалцахгүй; зөвхөн нууц SQL орчинд нэг удаа өгнө. 115091-ээр нэвтрэх нь manager болохыг батлах цорын ганц нөхцөл **биш**: \`access_role=manager\` сервер дээр хадгалагдана.
5. HTTPS staging нээж менежерээр нэвтэрч, **Ажилтан бүртгэх** таб дээр жишээ ажилтан үүсгэнэ. Ажилтнаар нэвтэрч, өөрийн ээлж, цалин, кассын зөрүү л харагдаж буйг шалгана.
6. Хуучин Google Sheets / opensheet public endpoint-уудыг **хааж, Sheets sharing-ийг Private** болгоно. Хуучин public snapshot болон хуучин PIN/нууц үгийг цааш ашиглахгүй; хүн бүрт шинэ PIN олгоно.
7. Зөвхөн хамгаалалт, эрхийн шалгалт, ээлж/цалингийн тооцоолол баталгаажсаны дараа \`main\`-д merge хийнэ.

## Хамгаалалтын анхааруулга

4 оронтой PIN нь 10,000 боломжтой учраас дан нууц үгээс сул. Хэрэглэгчийн хүсэлтээр нэмэлт OTP/MFA шаардаагүй боловч rate limit/lockout, HTTPS, HttpOnly cookie болон серверийн салбарын эрхийн шалгалт заавал хэвээр байна. Бодит ажилчдын мэдээлэл ашиглахаас өмнө PIN-ийн эрсдэл, төхөөрөмж хуваалцах эрсдэл болон нэвтрэх оролдлогын хяналтыг шалга.

Бүх код энэ branch дээр байгаа нь **deploy хийсэн гэсэн үг биш**. UI JavaScript синтакс, API JavaScript синтакс шалгасан; бодит сервер, DB, хэрэглэгчээр end-to-end тест хараахан хийгдээгүй.
